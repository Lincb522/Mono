# Design System: Mono BLOUD Player

## Overview

This document scopes the implemented `BLOUD` player theme and its BLOUD / PAW SHIBA / PAW CAT companions; Mono's default theme is unchanged.
The round character and eye geometry reference [Bloub](https://bloub.vercel.app/) and [jeremy-prt/bloub](https://github.com/jeremy-prt/bloub), licensed under MIT; upstream attribution is preserved in the bundled `Bloub-LICENSE.txt`.
Keep Mono's functional playback language and existing sheets. The character maps provider genre and mood tags to a visual expression; it does not describe a listener's mood.

## Colors

`BloudPlayerLayout` owns adaptive ink and paper: light `#111214` / `#F7F8FA`, dark `#F2F3F4` / `#151719`.
The default BLOUD character uses ink, its eyes use paper, and the play key reverses those roles. Cover-derived color accents the default orbit marker. Each companion stores its own optional custom color; selecting one derives the player surface, text, secondary text, controls, orbit, character panel, and three-dot menu from that color. PAW SHIBA defaults to its original orange fur; PAW CAT defaults to white. BLOUD has no body outline, including with custom colors. White or black eye/primary-action ink is selected by contrast. Reset restores the selected companion's default palette.
Secondary text and the orbit track use ink opacity; contrast remains a runtime verification requirement.

## Typography

Use system semantic text styles: rounded bold large title for the song, rounded heavy title3 for the theme name, body for artist, headline for play, and caption within the expression picker.
Time uses monospaced subheadline digits. Song and artist text can wrap vertically; retain localized complete labels.

## Layout

The toolbar sits above scrollable content. The character and details stack vertically by default.
Above 660 points, landscape containers use a horizontal arrangement unless Dynamic Type is an accessibility size; character diameter is capped at 420 points.
Accessibility text sizes stack play and skip controls. The three secondary icon actions share one compact horizontal row, and the expression grid uses adaptive columns.
These are source-level layout intentions, not verified device-size coverage.

## Elevation & Depth

The surface is flat and uses tonal separation without character shadows. Orthographic tangent-frame projection attaches the eyes to the spherical head as yaw, pitch, and roll change.

## Shapes

Preserve the circular BLOUD head, capsule-like eyes, thin circular seek orbit, capsule play key, and unlabeled character stage. The PAW companion reconstructs the approved front-facing `PawPrintIcons/profileFilledHead` design with hand-authored vector paths. That image is a visual reference only; the player must not load, composite, trace pixels at runtime, or display it. Preserve the reference silhouette, ears, muzzle, brow dots, outline and blush.
A non-cancelling window gesture observer, scoped to the player bounds, steers gaze from all touches including control taps. A zero-distance drag gesture in the circular character area suspends the surrounding scroll view for the duration of contact; gesture state resets on release or cancellation. The window observer supplies general touch/hover gaze. Direct character drags also supply normalized origin, location and translation, and PAW prioritizes those coordinates for gaze and contact feedback. The outer seek ring and the rest of the scrollable content keep their existing interactions. A critically damped spring preserves position and velocity across gaze targets, including while playback is paused. The last touch is held for 0.9 seconds before a slower spring return. Supported pointer and Pencil hover can guide gaze before contact; ordinary iPhone touch cannot locate a hovering finger. The opt-in camera mode uses front-camera hand-pose detection to provide a gaze target before contact, while an active touch or pointer gesture takes priority. Playback belongs to the separate play key; seeking belongs to the surrounding orbit.

## Components

- `BloudExpression.swift` owns 24 eye expressions, pose interpolation data, and catalog-tag mapping. Specific genre/mood tags take priority over broad Pop labels; matching accepts Chinese and English tags and preserves Latin word boundaries.
- `BloudListeningModel.swift` owns separate automatic/manual selections for BLOUD and PAW, both using the same current-song metadata request. Each companion resolves its own expression directly from tags, independently of playback, PCM availability, and AI tuning. Inline `Song.genreTags` resolve immediately; otherwise the current source supplies tags with a ten-second wait limit. The request token and source-qualified song identity reject retired results. A late inline-tag update restarts unresolved preparation.
- `SongGenreMetadata.swift` parses Netease song basic blocks (`songTag` and `songBizTag` resource titles), provider tag sections, and embedded file genre fields. QQ requests song labels directly; Qishui and Kugou reuse platform detail tags; Apple Music preserves `genreNames` during conversion and can retrieve missing catalog genres. Local imports persist embedded genres, with on-demand file reads for older imports. ID3 numeric TCON references use zero-based genre IDs; MP4 predefined `gnre` values use one-based IDs, read from numeric or two-byte big-endian metadata values.
- There is no audio, title, artist-name, AI, or stored-DNA fallback for expression selection. Missing or unsupported metadata leaves the default calm expression unresolved. Recognized metadata locks the song's expression; manual selection and the automatic choice survive closing and reopening the player in the same process. A different track resets both; no cross-launch expression persistence is implied.
- `BloudCharacterView.swift` owns Canvas rendering, spherical projection, finger-following gaze, blink, and eyelid micro-expressions. Live RMS rises and low-band attacks cue nine eye-only reactions: a full blink, a soft bilateral squint, a left or right wink, brief widening, a left or right eye lift, an asymmetric squint, or a slow blink. Strong and softer attacks use bounded variation sequences that avoid consecutive repeats; each reaction eases back to the song's unchanged base pose. Audio never changes the head radius, center, yaw, pitch, or roll; gaze alone steers the head. After a strong-attack reaction, further rhythm reactions wait at least 3.2 seconds; after a softer reaction, they wait at least 2.2 seconds. The attack thresholds remain 0.28 for a reaction and 0.7 for a strong reaction, filtering minor fluctuations.
- Playback motion pauses when inactive, obscured, not playing, or Reduce Motion is enabled. Gaze and expression transitions retain a bounded settling window while paused. The pre-effect observer follows a cancellable task and uses a newest-only frame buffer at 20 Hz. Without PCM, including protected Apple Music playback, the character retains resting blink and gaze but does not synthesize rhythmic micro-expressions from BPM. Catalog expression selection still works independently.
- `PawExpression.swift` owns 24 canine expressions and PawFacePose/PawEyePose geometry, with no BloudExpression or BloudFacePose conversion. Eyes morph between rounded eyes, upward smile arcs, and downward sleep arcs; hopeful/pleading eyes use clipped catchlights. The smaller mouth has an independent smile, opening, roundness and asymmetry. Ear fold, blush, gentle head tilt and resting gaze are authored per expression. PawTagExpression maps provider tags directly to canine moods. Pose changes blend all PAW features over 0.55 seconds and preserve the current pose when interrupted. The PAW SHIBA and PAW CAT tabs, main character, entry icon, accessibility value and idle-action selection use this independent type.
- `BloudPawArtwork.swift` draws the complete dog using SwiftUI Path geometry in a centered 120-point square: head and ear contour, both inner ears, muzzle/cheek fur, brow dots, blush, nose, mouth and eyes. Paths are static values, with no image imports, bitmap decoding, masks extracted from assets, or asynchronous preparation. The default fur uses `F4AE58`; custom color directly fills the fur layer while cream, outline and blush retain their own colors. Eye geometry, brow positions, mouth shape, blush, ear poses and resting head tilt derive exclusively from the interpolated PawFacePose; the gaze spring shifts the facial features slightly, and audio changes eyelid openness only. Surprised poses smoothly replace the closed mouth with an open mouth. The reference proportions are reviewed through an SVG export of the Swift paths; native rendering and exact visual equivalence remain unverified without a build.
- `BloudPawMotion.swift` owns temporary contact feedback, independently of the song expression. A high-priority zero-distance drag feeds a GestureState contact; release and cancellation use the same spring return. Cheek contact gently stretches the selected cheek outward and follows the finger locally. The head stays almost upright: contact displacement is 0.35 points and tilt 0.6 degrees in the 120-point canvas; whole-head drag is attenuated during a pinch. The eye and mouth reaction is limited to mild reluctance, with minimal ear movement. A 0.28-second onset and 0.9-second tap release replace the sharp recoil. Dragging adds bounded translation and tilt. Forehead contact softens the eyes and ears and shows the tongue; nose contact prompts a lick. Quick taps receive a complete short envelope even after release. One soft haptic occurs on contact, through the existing haptic manager. A localized VoiceOver Pet PAW action triggers the forehead response.
- PAW has four occasional playback actions: a brief tongue-tip peek, ear flick, nose lick, and yawn; drowsy/sleeping PAW expressions start with a yawn. Actions last at most 1.65 seconds, spaced on a 16-second cycle, and contact suppresses them. The tongue peek lasts 0.96 seconds with a 0.22-second hold, a closed smiling mouth and slightly relaxed eyes. Its Figma-authored short rounded pale-pink tip sits behind the mouth stroke, with no outline or center crease; it does not use an open panting mouth. They are not triggered by every beat and do not change the selected expression. Playback pause or an obscured/inactive player suppresses idle actions; direct touch feedback still works while paused. Reduce Motion uses a static contact expression with no drag, dodge, ear deformation, gaze parallax or idle action. The same analytic gaze spring keeps drag retargeting and release continuous; timeline settling stops after release.
- The existing companion panel has a persistent BLOUD / PAW SHIBA / PAW CAT segmented tab control above the scrolling content. Each tab shows only that companion's expression thumbnails and its own color picker/reset control. Switching tabs selects the player companion. Each tab has an independent manual selection and automatic song expression; choosing or resetting one never changes the other. All manual choices reset when song identity changes. Companion selection and all three colors persist in AppStorage.
- `BloudProgressOrbit.swift` owns playback-time observation, drag seeking, the marker, and formatted time. VoiceOver adjustment seeks in five-second steps, bounded to duration.
- A native “Gaze tracking” (视线追随) toggle sits at the top of the three-dot menu, follows the menu palette, defaults off, and preserves the existing stored preference. No camera switch remains below the player actions. Camera authorization is requested only after enabling it. Denial exposes Settings; camera absence, interruption, or processing failure exposes recovery text and Retry.
- `BloudHandTracker.swift` scopes capture to the visible, unobscured BLOUD player while the scene is active. A serial capture queue owns the video-only 640×480 session and Vision request, with at most 24 analyses per second and late-frame dropping. Automatic audio-session reconfiguration is disabled; no microphone input is added.
- Captured pixels are rotated to the current window orientation and mirrored once before Vision. Fingertip and face landmarks become normalized camera-space gaze targets. Input preserves spring velocity while retargeting; loss returns more slowly. This follows subject position in the camera image and does not predict which on-screen button an airborne finger will press.
- No camera preview, photo/video persistence, or network transport is created. The app's localized camera usage description explains this local processing. Capture and observers stop on cancellation, disabling the switch, leaving the player, opening another surface, or entering the background.
- `BloudMotion.swift` owns analytic gaze integration and live eyelid attack envelopes.
- `BloudTouchObserver.swift` attaches and detaches non-preventing touch and hover recognizers without cancelling or delaying native controls. `BloudLikeButton.swift` uses the shared favorite manager and observes the local playlist state; the existing playlist-choice preference is preserved.
- Lyrics, queue, and transport controls use `MonoIcon` and the configured custom icon pack. The expression entry uses a 30-point rendering of the selected companion in its attentive pose. Expression, lyrics, and queue entries have 48-point hit targets and localized accessibility labels without visible text. Theme selection displays `BLOUD`; the player header follows the selected companion and displays `BLOUD`, `PAW SHIBA` or `PAW CAT`. No expression label appears below the character.
- `BloudPlayerLayout.swift` owns composition, palette, transport, expression selection, loading state, and integration with existing lyrics, queue, theme, quality, and audio-center surfaces.
- Accessibility source provisions include semantic buttons, localized labels, selected expression traits, an image/value description for the character, and 44–56-point action heights.

## Do's and Don'ts

- Keep automatic and manual expression identity independent of real-time audio motion; do not turn the character into a transport button.
- Preserve current-song identity checks around metadata requests and cancellation; do not mutate EQ as a side effect of visual characterization.
- Keep this document scoped to Bloud. Shared theme selection, measurement, playback, localization, and license packaging remain owned by their existing sources.
- Native visual rendering, device/runtime behavior, Swift typechecking, and XCTest are **unverified**: the user prohibited builds; no native runtime validation was performed for this work. Reflow, contrast, accessibility, and minimum-runtime behavior require later native verification.

- `PawCatArtwork.swift` uses Figma component 28:3's exported SVG as canonical geometry. All 16 shapes are normalized from 480 to 120 points without changing their coordinates. The base fur is F4F2F3, contour/eyes are 171717, pink is FFAFB5, stripes CECCCC, whiskers 383838; stroke widths are 3.5/2.4/1.3 points. Cat rendering adds no fur gradient or snout scaling. Neutral eyes retain the SVG's slightly different left ellipse and right circle, and the neutral mouth retains its exact cubic paths. Expression and gesture offsets are applied on top of that geometry. Cat and shiba share tag-to-animal-mood resolution but own independent manual choices and color storage. The shiba retains raw selection value `paw` and its existing color key. SVG-to-Swift coordinate checks and static path exports are available in `artifacts/paw-cat-figma-20260915`; native rendering and device interaction remain unverified.

- PAW SHIBA was refined as editable Figma component 28:648 before adopting its exported SVG. The 480-point paths are normalized to 120 points: white muzzle has a continuous shallow bridge without the former central notch, eyes are 12-point circles, brows are 7 by 7.2 points, outline is 3.6 points and mouth stroke 2.5 points. Neutral colors follow the flat Figma fills; the renderer preserves expression, gaze and contact overlays. Native app rendering remains unverified without a build.

- Tongue tips are authored in Figma components 28:692 (shiba) and 28:707 (cat), rooted at (60, 77.2) and (60, 74). They use mouth-shaped upper boundaries and rounded tips, F5A6B0 fill, no stroke/crease, and sit beneath the mouth. A static path clip keeps both tongue roots below the mouth while their tips extend; licks use the same rooted extension without rotating or lifting the root. Cat contact and idle motion have their own branch: forehead petting squints, nose contact produces a small sniff, and gentle cheek contact closes the eyes slightly. Cat playback alternates slow bilateral blink, whisker attention, sniff and slight ear listening over quiet 19-second cycles. Rest blinks take 0.8 seconds per 8.7-second interval; rhythm only contributes a restrained 20-percent eyelid response without widening. Pause suppresses idle activity; Reduce Motion disables nose/whisker/ear/drag displacement while retaining a static contact expression. Figma previews are static pose studies, not playback verification.

- Camera gaze uses normalized lens coordinates directly in every companion, independent of player layout, with 1.4x center gain and a 19-response gaze spring during input. PAW gaze moves the whole head, with secondary eye travel relative to the face (cat 3.2/2.0 points; shiba 3.0/1.8). Capture prefers the front TrueDepth camera when available, otherwise the front wide camera; RGB frames are processed locally by Vision, without Face ID authentication or biometric identity data. Hand selection evaluates all five fingertips by confidence, extension and continuity, with palm fallback. After a brief 0.18-second hand occlusion hold, face landmarks supply the eyes midpoint of the largest face. Capture targets 30 fps when supported, face landmarks are limited to 15 Hz, and late frames are discarded. Focus accepts confidence >=0.35, filters only sub-0.0015 jitter and retains its existing 0.45-second missing-target release. The user opt-in, touch priority, cancellation, scene/menu suspension and camera error paths remain shared by all three companions. Camera performance and native tracking are unverified without device execution.

- PAW applies the smoothed gaze to the complete portrait before rendering its outline, ears, fur and features. Horizontal/vertical gaze produce bounded translation, a small roll, and subtle foreshortening; facial offsets are smaller to keep the features attached. Touch, hover and camera share this head response. Cheek pressure attenuates the gaze turn to preserve gentle pinching, and the combined translation/roll are bounded to 8/6 points and 9 degrees. Audio never drives the head transform. Neutral gaze preserves the canonical SVG geometry; Reduce Motion passes zero gaze and retains its existing no-head-motion behavior.
